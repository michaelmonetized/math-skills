# Triangulate

Feedback on mathematics arrives in a heap: a referee report with forty points, an email saying "I think Lemma 4.2 is wrong", a coauthor's margin notes, open issues on the paper's repository. This skill splits the heap into items, verifies each against the manuscript, and moves it through a state machine.

Every comment posted to a shared tracker during triangulation starts with:

```
> *This was generated by AI during triage.*
```

Never post to a shared tracker, email anyone, or reply to a referee or editor without the user's explicit go-ahead for that specific message.

## Roles

Category (exactly one per item):

- `error`: a claimed mathematical mistake: a false step, a false statement, a counterexample.
- `gap`: a step that may be true but is not justified.
- `exposition`: unclear writing, notation, missing definitions, typos.
- `literature`: a missing, wrong, or unverified reference; a claim of prior work.
- `extension`: a suggestion to generalise or strengthen.

State (exactly one per item):

- `needs-triage`: not yet evaluated.
- `needs-info`: waiting for the reporter (e.g. "which version of the preprint?").
- `ready-for-agent`: fully specified; an agent can fix it alone.
- `ready-for-human`: needs the author's judgement (any change to a main statement, any disagreement with a referee).
- `wontfix`: will not be acted on, with the reason recorded.

The actual label strings may differ in this project; the mapping comes from `/setup-math-pocock-skills`.

## Invocation

The user describes what they want in natural language: "triangulate the referee report in `reports/ref1.pdf`", "what needs attention?", "move the Lemma 4.2 issue to ready-for-agent".

## Triangulate a batch

1. **Split** the source into atomic items, one claim each, quoting the source and the location in the manuscript (section, equation, page and line).
2. **Verify each item yourself before categorising.** For an `error`, try to reproduce it: check the step, run a small case, build the claimed counterexample (call the Skill tool with "diagonalizing-bugs" if it is not immediate). For `literature`, look the reference up (`researxiv`). Report: confirmed, refuted (with the reason), or unclear.
3. **Categorise and set state.** Confirmed errors that touch a main result are always `ready-for-human`. If an item is unclear and the user is present, grill it (call the Skill tool with "epsilon-delta-grilling").
4. **Write an agent brief** for each `ready-for-agent` item: the location, the problem, the intended fix, and how to confirm it (the check to run, the sentence that must change). Write it to survive later edits: name labels and statements, not page numbers alone.
5. **Summarise**: a table of items by category and state, with confirmed errors first.

## Responding to a referee

When the source is a referee report, also draft a response document for the user: each referee point quoted, followed by the action taken (with the new location) or a polite, specific reason for not acting. The user edits and sends it.

## What needs attention?

List items in `needs-triage`, then `needs-info` items whose reporter has replied, then `ready-for-human`, oldest first, one line each.
